> **日期**：2026-09-12  
> **来源**：`ZL.Gear.Docs/143`、`146`

---

## 一、产品定位（一句话）

**Gear.NET = Headless 测试序列框架（瑞士军刀单站 ATE 编排内核）**

| 我们是什么 | 我们不是什么 |
|------------|--------------|
| **执行器**（`SequenceExecutor`）+ **评估器**（`ResultEvaluator` / Assert 分离）+ **微流程/配方 DSL**（`MicroWorkflow` + `DynamicFlow` JSON） | MES、可视化设计器、插件市场、通用 BPM |
| 可插拔 **行业 Handler**（`IGearExtension`）与 **宿主 Demo** | 仪器驱动、PLC 现场协议、客户产线业务 |
| NuGet 发 **框架 DL**，Demo 用 WinForms/CLI **展示** | 把 ConsoleApp 或 Seat 当框架卖 |

对标 OpenTAP/TestStand 学 **形态**（Step 插件 + Plan 数据解耦 + 执行≠评估）。

## 三、框架 DL 内涵（你要发布的「核心」）

按产品诉求：**执行器 + 评估器 + 微流程** —— 与实码映射如下。

| 能力 | 主要实码位置 | 程序集 |
|------|--------------|--------|
| **微流程 / 配方 DSL** | `MicroWorkflow`、`WorkflowNode*`、`WorkflowEvaluator`；JSON 构建 `DynamicFlowHandler` | Core + Engine |
| **执行器** | `SequenceExecutor`、`SequenceExecutorBuilder`、`StepDispatcher`、中间件管道 | Engine |
| **评估器** | `IResultEvaluator` / `ResultEvaluator`；JSON `Assert`；`EvaluateResult` 桥接 | Engine |
| **扩展缝** | `IGearExtension`、`RegisterHandlerWithAction`、`ModuleLoader.LoadModules` | Engine |
| **参数/作用域** | `StepArgsReader`、`ContextVariableStore.SetShared` | Core |

**明确不属于「框架 DL」、属业务/适配：**

| 能力 | 实码 | 为何不算框架 |
|------|------|--------------|
| 仪器驱动实例化 | `ZL.Gear.Drivers` → `UnifiedDeviceFactory` | 客户设备/协议/闭源 DLL |
| 传输/VISA/USB | `ZL.Gear.Communication` + `libs/` | 不可公开还原 |
| 行业步骤 | `Extension.Station`、Seat、客户 Handler | 换行业换扩展包 |
| 演示宿主 | ConsoleApp、IndustryKit Client、规划 WinForms | 仅展示与门禁 |

### Sensing 边界说明

- **Drivers**：用户口径中的「驱动/业务」——**不随框架 NuGet 发布**。
- **Sensing**：采样/`GenericMeasure` 实现，**仅依赖 Core**，无 Drivers/Communication 引用。
- **但**：`ZL.Gear.Engine.csproj` **编译期 ProjectReference Sensing**；`ModuleLoader` 默认 `BuiltInModules.All` 会注册 Sensing Handler。
- **结论**：Sensing **不是** Drivers 那种闭源传输层，但也 **不是** 纯 L-DSL；更接近 **框架自带的「测量适配参考实现」**。
  - **短期**：随 Engine 同仓维护；是否单独 NuGet **待定**（非阻塞发布 Core+Engine）。
  - **长期**：若坚持「框架零测量实现」，需单独立项拆 `BuiltInModules.Sensing` 为可选包（**大动**）。

## 五、NuGet 发布策略（双轨交付）

### 5.1 轨道 A — 公开 NuGet（通用框架）

| 包 ID | 内容 | 消费者得到什么 |
|-------|------|----------------|
| `ZL.Gear.Core` | 微流程 + 契约 + StepArgsReader | 配方/变量/表达式基础 |
| `ZL.Gear.Abstractions` | 扩展点与设备类型抽象 | 自定义 Handler / 驱动契约 |
| `ZL.Gear.Sensing` | 采样与信号绑定 | Continuous / Threshold 等 Sensing 能力 |
| `ZL.Gear.Engine` | 执行器 + 评估器 + DynamicFlow + ModuleLoader | 可跑 **逻辑类** DynamicFlow（`BuiltInModules.Core`） |
| `ZL.Gear.Extensions.Data`（可选） | 结果存储 | CSV/SQLite 等 |

**CI 发布**：`pipeline.json`（5 包 · `obfuscate: false`）+ `.github/workflows/publish.yml`（tag `v*` → NuGet.org OIDC）。

**Engine 发包前置条件（2026-09-12 已满足）**：

1. ✅ 无 `Engine.csproj` → Drivers 的 `ProjectReference`
2. ✅ `CreateDefaultDeviceService()` 默认 `NullDeviceService`
3. ✅ `ZL.Gear.Drivers` 侧 `AddGearDrivers()`；ConsoleApp 显式注入（私有仓）
4. ✅ `SimpleTestExecutor` 已迁出 Engine
5. ✅ Engine **无** `ZL.License` 硬依赖（公开轨 LogicOnly）

### 5.2 轨道 B — 同仓/私有（仪器全栈 · 非框架）

| 组件 | 交付方式 |
|------|----------|
| Drivers + Communication + `libs/` | 源码同仓或私有 feed；**不**冒充框架 NuGet |
| Seat / Bus / 客户 Extension | 业务仓库或 `samples/` |
| Mock 场景与 `devices.json` | ConsoleApp / Demo 宿主附带 |

**禁止幻觉**：「只引 Engine NuGet 即可 FullIntegration 接真实 VISA 仪器」—— **当前不可行**，除非轨道 B 一并交付。

## 六、依赖图（诚实版）

```text
Core                    （无项目引用）
  ↑
  ├── Abstractions
  ├── Sensing
  ├── Extensions.Data
  ├── Communication ← libs/*.dll（闭源）
  │     ↑
  │   Drivers
  │     ↑
  └── Engine ←── Sensing
        ↑       └── Drivers（编译期硬引用 · 仅 2 处 new + SimpleTestExecutor）
        │
   ConsoleApp（显式 Engine + Drivers + Sensing）
   IndustryKit Client（仅 Engine · transitive Drivers）
```

**「Drivers 陷得太深」的真正瓶颈是 L3（Communication 闭源）**，不是 Engine 里两行 `new`。

## 八、注意事项

- **禁止**把 `Gear.All/` 整包 push（一次性泄漏 Drivers + Docs + libs）
- **禁止**在 Drivers/Exts **复制** `ZL.Gear.Core` 源码
- **禁止**把 `ZL.Gear.Docs` 内容复制进公开 `ZL.Gear`
- **禁止**提交 `libs/*.dll` 到任何远程仓
- 公开 **ZL.Gear** 前须满足 G0 门禁 + filter-repo 后再公开
- `ZL.Gear` 公开前 **不含** `docs/` 商业/战略正文
