# Engine 解耦与宿主策略

> **日期**：2026-09-12  
> **来源**：`ZL.Gear.Docs/142`、`145`、`146`  
> **用途**：Engine 与 Drivers 解耦现状、显式宿主 API、Build 门禁、消费方使用范式。

---

## 一、解耦背景

当前 `ZL.Gear.Engine` 在项目中被定位为**核心编排器**，但其项目文件曾直接引用 `ZL.Gear.Drivers`，而 `ZL.Gear.Drivers` 又进一步依赖 `ZL.Gear.Communication`。
`ZL.Gear.Communication` 因硬编码引用闭源硬件 DLL（`libs/Ivi.Visa.dll`、`libs/LibUsbDotNet.LibUsbDotNet.dll`、`libs/NationalInstruments.Visa.dll`）且这些 DLL 被 `.gitignore` 排除，**无法作为 NuGet 包发布**。

若 Engine 不发布，则整个 Gear.NET 框架对外只留下抽象层，消费者无法获得"核心编排能力"，发布失去产品意义。

## 二、现状耦合度审查

### 2.1 Engine 项目引用（Phase 1 已处理）

| 文件 | 引用内容 | 处理结果 |
|------|---------|----------|
| `ZL.Gear.Engine.csproj` | `ProjectReference` 至 Drivers | ✅ 已删除 |
| `SequenceExecutorBuilder.cs` | `using ZL.Gear.Drivers.Core;` + `new UnifiedDeviceFactory()` | ✅ 已改为 Core 抽象 + 显式注入 |
| `SimpleTestExecutor.cs` | `using ZL.Gear.Drivers.Core;` + `new UnifiedDeviceFactory()` | ✅ 已迁出 Engine → ConsoleApp |
| `ModuleLoader.cs` | 反射按程序集名 `ZL.Gear.Drivers` 查找 `PlcStepHandler` | ⚠️ 软依赖（无编译期引用）；失败只打日志 |

### 2.2 关键发现

**事实**：Engine 的"骨架"早已通过 Core 抽象与 Drivers 隔离，**只有"默认肌肉"路径绑定了 Drivers 具体实现**。

Engine 核心运行时（`SequenceExecutor`、`StepDispatcher`、`DynamicFlowHandler`、`StandardActionsProvider`）对设备的访问**全部通过 Core 抽象层接口**：

```csharp
// SequenceExecutor.cs
private readonly IDeviceService _deviceService;

// DynamicFlowHandler.cs / StandardActionsProvider.cs
var device = ctx.GetDevice<IDevice>(targetId);
```

Core 层已完整定义：

```csharp
public interface IDeviceService
{
    Task<IDeviceLease<TDevice>> LeaseAsync<TDevice>(string deviceKey, CancellationToken token = default)
        where TDevice : class, IDevice;
    Task InitializeAllDevicesAsync(int maxParallelism = 4, CancellationToken token = default);
    Task EmergencyStopAsync(CancellationToken token = default);
}

public interface IUnifiedDeviceFactory
{
    IDevice CreateDevice(string deviceCode);
    IReadOnlyDictionary<string, IDevice> GetAllDevices();
    void CreateAll();
}
```

Drivers 侧 `UnifiedDeviceFactory` / `UnifiedDeviceService` 已实现 Core 的 `IUnifiedDeviceFactory` / `IDeviceService`。这意味着：**把 Drivers 从 Engine 的隐式依赖改成显式依赖，不需要修改 Drivers 的任何实现代码**。

## 三、显式宿主策略（145 最优方案）

### 3.1 两种宿主（零隐式默认）

| 宿主类型 | 引用 | 必须调用 |
|----------|------|----------|
| 行业模板 / 纯 DynamicFlow / Demo | 仅 Engine + Core 扩展 | `.AsLogicOnlyDemoHost()`（自动锁 `BuiltInModules.Core`；禁止 `WithDeviceConfig`） |
| ConsoleApp / WinForms / 产线 | Engine + **Drivers** | `.AsInstrumentedHost(deviceService)` 或 `.WithDeviceService(svc)` |

### 3.2 设备服务来源

| 方式 | 说明 |
|------|------|
| `DriversServiceCollectionExtensions.CreateDeviceService()` | Drivers 侧辅助方法，返回 `(IDeviceService, IDisposable)` |
| DI `AddGearDrivers()` | 在宿主 `Program.cs` 中注册singleton |

### 3.3 Build 门禁（核心 · fail-fast）

`Build()` 在 `CreateDefaultDeviceService()` **之前** 执行门禁：

```csharp
if (_deviceHostMode == DeviceHostMode.Unspecified)
{
    throw new InvalidOperationException(
        "未声明宿主类型。Demo/IndustryKit 请调用 AsLogicOnlyDemoHost()；" +
        "产线/ConsoleApp 请调用 AsInstrumentedHost(IDeviceService)（配合 DriversServiceCollectionExtensions.CreateDeviceService()）。");
}

if (_deviceHostMode == DeviceHostMode.LogicOnly)
{
    if (!string.IsNullOrEmpty(_deviceConfigPath))
        throw new InvalidOperationException("LogicOnly Demo 宿主禁止 WithDeviceConfig。");
    if ((_builtInModules & (BuiltInModules.Sensing | BuiltInModules.Plc)) != 0)
        throw new InvalidOperationException("LogicOnly Demo 宿主仅允许 BuiltInModules.Core。");
}
```

### 3.4 默认行为变更

| 项 | Phase 1（现） | 145 最优 |
|----|---------------|----------|
| 未注入 IDeviceService | 静默 Null | **Build throw** |
| `_builtInModules` 默认 | `All` | **`Core`** |
| LogicOnly + device config | 允许 | **Build throw** |
| Null Init/EStop | 空操作 | **throw** |
| IndustryKit | 隐式兼容 | **显式 Demo API** |

## 四、消费方使用范式

### 4.1 纯逻辑 / Demo（无真实设备）

```csharp
var executor = SequenceExecutorBuilder.Create()
    .AsLogicOnlyDemoHost()
    .WithBuiltInModules(BuiltInModules.Core)
    .WithExtension(new StationExtension())
    .Build();
```

### 4.2 产线 / 真实设备（显式注入）

```csharp
var (deviceService, res) = DriversServiceCollectionExtensions.CreateDeviceService();
using (res)
var executor = SequenceExecutorBuilder.Create()
    .AsInstrumentedHost(deviceService)
    .WithBuiltInModules(BuiltInModules.All)
    .WithDeviceConfig("Protocols/devices.json")
    .Build();
```

### 4.3 旧示例（已废止）

| 旧示例 | 状态 | 145 目标写法 |
|--------|------|-------------|
| 裸 `.Create().Build()` | **[已过期]** | 须 `.AsLogicOnlyDemoHost()` 或 `.AsInstrumentedHost(svc)` |
| `.WithDeviceService(new UnifiedDeviceService(...))` | **[已过期]** | 须 `.AsInstrumentedHost(deviceService)` |

## 五、灾难风险与回滚策略

| 风险项 | 级别 | 触发条件 | 防护措施 |
|-------|------|---------|---------|
| **Breaking Change：默认构造行为改变** | 中 | 现有用户代码直接 `new SequenceExecutorBuilder().Build()` 不传 `IDeviceService` | 145 后 Build 直接抛 `InvalidOperationException`，**禁止**静默 Null |
| **SimpleTestExecutor 迁移导致 ConsoleApp 编译失败** | 低 | 移动文件后 using 路径未更新 | 迁移后一次性改完所有引用 |
| **ModuleLoader 反射注册 Plc 失败** | 极低 | 反射依赖程序集已加载 | 保持现状，已经是软依赖，失败只打日志 |
| **NuGet 消费者还原后运行期授权异常** | **高（硬性阻塞）** | Engine 依赖 `ZL.License`（2.2.6），若该包未发布到 NuGet.org 或私有源，消费者无法还原包 | **发布前必须确认 `ZL.License` 的 NuGet 可用性** |

### 回滚策略

- **Git 回滚**：所有改动集中在 Engine 的 2-3 个文件 + 1 个 csproj + 1 个文件迁移，回滚成本极低。
- **二进制兼容过渡**：145 后是 **breaking change**（Build throw），但发生在开发期，现场产品已在跑但新组合根模式尚未被 10-20 个项目复制。
