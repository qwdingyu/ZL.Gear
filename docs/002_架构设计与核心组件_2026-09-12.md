## 一、三层产品面（必须对外口径一致）

| 层 | 实码位置 | 是什么 | 不是什么 |
|----|----------|--------|----------|
| **L-DSL** 步内微流程 | Core：`MicroWorkflow` / `WorkflowNode*` / `WorkflowEvaluator`；Engine：`DynamicFlowHandler` + **StandardActions 中无设备子集**（Delay/Log/Assert/Calculate/SetVariable/Sync.* 等） | JSON/Fluent 把配方编成步内编排 | 不是整次测试会话；不是 BPM；不是 soft PLC |
| **L-Test** 测试运行器 | Engine：`SequenceExecutor` + `StepDispatcher` + `ResultEvaluator` + EventBus / `TestRunResult` | 租设备、Profile、SubSteps、ExpectedResults、StopByFail、会话结局 | 不是横切「通用执行器」中间件 |
| **L-Adapter** 工业适配 | **默认内置**：Sensing（`UniversalActionProvider`/`TriggeredMeasure`）、AI Handler；**条件**：PLC（反射）；**插件**：Seat 等 `IGearExtension`（**非** ModuleLoader 默认列表） | GenericMeasure、PLC 命令、行业 Handler；设备向 `Write`/`Read`/`Query` | 不是 DSL 内核；禁止死绑进「未来 Workflow.Engine」 |

> **纠正**：勿写「Seat = ModuleLoader 默认注册」。Seat 工程引用 Core+Drivers+Sensing、**可不引用 Engine**，由宿主 `LoadModules` 装入——示范的是扩展缝，不是「薄 DSL 插件」。

```text
宿主一次跑测
  └─ L-Test  SequenceExecutor（租约 / 步骤树 / 评测 / 报告）
        └─ StepDispatcher → Command
              ├─ DynamicFlow ──► L-DSL（MicroWorkflow）
              └─ 其它 Handler ──► L-Adapter（内置 Sensing/AI · 条件 PLC · 插件 Seat …）
```

**灾难型过抽取**：把 L-Test + L-DSL + L-Adapter 捆成一个「通用类库」卖给非电检团队。

## 二、模块职责矩阵

### 2.1 框架层（拟发布 · NuGet 轨道 A）

| 模块 | 程序集 | 是什么 | 负责（IN） | 不负责（OUT） |
|------|--------|--------|------------|---------------|
| **L-DSL 契约** | `ZL.Gear.Core` | 配方 DTO、变量、表达式 | `StepConfig`、`StepArgsReader`、`IGearExtension`、`IDevice`/`IDeviceService` **接口**；**步内** `WorkflowEvaluator` | 执行循环、驱动实例、UI、顶层 OverallSuccess |
| **L-Test 运行器** | `ZL.Gear.Engine` | 一次跑测会话 | `SequenceExecutor` **独占**租约扫描/Lease、`StepDispatcher`、**顶层** `ResultEvaluator`、`DynamicFlowHandler`（JSON 解释）、`BuiltInModules` 注册 | 具体 VISA/PLC 协议、行业配方语义、合格限值硬编码 |
| **L-Test 测量参考** | `ZL.Gear.Sensing`（Engine **编译引用**） | 框架同仓参考实现 | `UniversalMeasurer`、`GenericMeasure`；**运行期**由 `BuiltInModules.Sensing` 决定是否注册 | 行业 Handler；**不是** Drivers/Communication 同级闭源栈 |

> **Sensing 与产品定位对齐**：
> - **今码**：`Engine.csproj` 编译期引用 Sensing；默认 `BuiltInModules.All` 会注册 Sensing Handler。
> - **口径**：Sensing = **Engine 同仓测量参考实现**；**运行期**可通过 `BuiltInModules.Core` 不挂载（IndustryKit 已如此）。
> - **NuGet**：短期可随 Engine 同包或同 feed 发布；**不**与 Drivers/Communication 绑在一起发。
> - **否决方案**（Engine 移除 Sensing 编译引用、条件反射加载）：属 Phase 2 大动，**不在当前范围**。

### 2.2 适配层（业务/私有 · NuGet 轨道 B · **三者依赖不同 · 禁止捆包误解**）

| 子层 | 程序集 | 依赖 | 标记 | 负责（IN） | 不负责（OUT） |
|------|--------|------|------|------------|---------------|
| **L-Adapter Transport** | `ZL.Gear.Communication` | Core + `libs/` 闭源 DLL | 业务/私有 | 传输层抽象、协议栈 | 步骤树、租约、Assert |
| **L-Adapter Devices** | `ZL.Gear.Drivers` | Core + Communication | 业务/私有 | `UnifiedDeviceFactory/Service`、`devices.json` | 步骤树、JSON Assert、Engine 编译强引用（Phase 1 已断） |
| ~~L-Adapter Sensing~~ | — | — | **已上移 2.1** | Sensing **不是** Transport/Devices 同级闭源适配 | — |

**依赖图（诚实版）**：

```text
Core
  ├── Sensing（仅 Core）
  ├── Communication ← libs 闭源
  │     └── Drivers
  └── Engine ← Sensing（编译期；Drivers 已解耦）
```

### 3.1 已完成的 Phase 1（编译解耦）

| 项 | 实码状态 |

| IndustryKit 扩展仅引 Core | ✅ `Extension.Station` → `ZL.Gear.Core` |

### 3.2 Engine 代码中的硬依赖（已处理）

| 文件 | 引用内容 | 处理结果 |
|------|---------|----------|
| `SequenceExecutorBuilder.cs` | `using ZL.Gear.Drivers.Core;` + `new UnifiedDeviceFactory()` | 已改为 Core 抽象 + 显式注入 |

### 3.3 当前剩余耦合点

| 层级 | 深度 | 说明 |
|------|------|------|
| L0 编译 `new UnifiedDeviceFactory` | **浅** | Phase 1 已处理，仅 2 处 |

## 四、显式宿主策略（145 最优方案）

### 4.1 两种宿主（零隐式默认）

| 宿主类型 | 引用 | 必须调用 |
|----------|------|----------|
| 行业模板 / 纯 DynamicFlow / Demo | 仅 Engine + Core 扩展 | `.AsLogicOnlyDemoHost()`（自动锁 `BuiltInModules.Core`；禁止 `WithDeviceConfig`） |
| ConsoleApp / WinForms / 产线 | Engine + **Drivers** | `.AsInstrumentedHost(deviceService)` 或 `.WithDeviceService(svc)` |

### 4.2 API 设计

```csharp
// 枚举
public enum DeviceHostMode
{
    Unspecified = 0,   // Build 禁止
    LogicOnly = 1,     // Demo：无物理设备
    Instrumented = 2   // 产线：真实或 Mock 驱动
}

// Builder 扩展
public SequenceExecutorBuilder AsLogicOnlyDemoHost()
{
    _deviceHostMode = DeviceHostMode.LogicOnly;
    _builtInModules = BuiltInModules.Core;
    _customDeviceService = LogicOnlyDeviceService.Instance;
    _disposeDeviceService = false;
    return this;
}

public SequenceExecutorBuilder AsInstrumentedHost(IDeviceService deviceService)
{
    if (deviceService == null) throw new ArgumentNullException(nameof(deviceService));
    if (deviceService is LogicOnlyDeviceService)
        throw new ArgumentException("Instrumented 宿主不能使用 LogicOnlyDeviceService。");
    _deviceHostMode = DeviceHostMode.Instrumented;
    _customDeviceService = deviceService;
    _disposeDeviceService = false;
    return this;
}
```

### 4.3 Build 门禁（核心 · fail-fast）

```csharp
if (_deviceHostMode == DeviceHostMode.Unspecified)
{
    throw new InvalidOperationException(
        "未声明宿主类型。Demo/IndustryKit 请调用 AsLogicOnlyDemoHost()；" +
        "产线/ConsoleApp 请调用 AsInstrumentedHost(IDeviceService)（配合 DriversServiceCollectionExtensions.CreateDeviceService()）。");
}

if (_deviceHostMode == DeviceHostMode.LogicOnly)
{
    if (!string.IsNullOrEmpty(_deviceConfigPath))
        throw new InvalidOperationException("LogicOnly Demo 宿主禁止 WithDeviceConfig。");
    if ((_builtInModules & (BuiltInModules.Sensing | BuiltInModules.Plc)) != 0)
        throw new InvalidOperationException("LogicOnly Demo 宿主仅允许 BuiltInModules.Core。");
}
```

### 4.4 默认行为变更

| 项 | Phase 1（现） | 145 最优 |
|----|---------------|----------|
| 未注入 IDeviceService | 静默 Null | **Build throw** |
| `_builtInModules` 默认 | `All` | **`Core`** |
| LogicOnly + device config | 允许 | **Build throw** |
| Null Init/EStop | 空操作 | **throw** |
| IndustryKit | 隐式兼容 | **显式 Demo API** |

## 五、产线禁止清单（灾难防护）

| # | 禁止行为 | 依据 |
|---|----------|------|
| F-01 | Handler 内 `Variables.Set` 写流程变量 | 须 `args.SetShared` |
| F-02 | 产线限值用 `context.Get` / `StepArgSource.All` | 须 `ArgsOnly` + `TryRequire*` |
| F-03 | Assert L1 `Check` 写 `&&` / `\|\|` | 单条件拆多条 Assert |
| F-04 | Handler 私自 `new UnifiedDeviceFactory()` | 破坏租约独占 |
| F-05 | `SequenceExecutor` 内硬编码 `if (command=="PLC")` 路由 | 须 `BuiltInModules` + 注册表 |
| F-06 | Engine NuGet **强引用** Drivers/Communication 程序集 | Phase 1 已断 Drivers；Communication 永不进 Engine |
| F-07 | 产线用 LogicOnly + 配方含 `Target` | 145 L-2 预检 → `OverallSuccess=false` |
| F-08 | 产线限值靠 Handler `Success=false` 静默判 FAIL | 限值须 JSON Assert 或 `ResultEvaluator`；Handler `Success=false` **仅**硬中断/设备故障 |
| F-09 | LogicOnly 宿主接入 `StationManager` | `InitializeAllDevicesAsync` 须 fail-closed |
| F-10 | LogicOnly Build 时仍 `UnifiedDeviceLoader.Load` | 145A：LogicOnly **跳过**设备 JSON 加载 |

## 六、远期目标形态（仅门禁通过后 · 非本阶段工作）

```text
Gear.Workflow.Contracts  ← 节点 DTO、变量、表达式、Action 委托、取消/超时
Gear.Workflow.Engine     ← MicroWorkflow + DynamicFlow + 逻辑 Action 白名单
Gear.TestRuntime         ← 今日 SequenceExecutor 等（留在电检产品 ≈ TestStand 产品面）
Adapters                 ← Sensing / Drivers / Seat / AI（插件；禁 ProjectReference 死绑进 Workflow.Engine）
```

**抽库立项门禁（须同时满足）**：

1. 至少一个**真实**第二宿主（仓库/产品在跑）：只要逻辑 DSL，明确不要 Lease / ExpectedResults / 默认 Sensing。
2. 宿主接受冻结 **JSON 九种** `WorkflowNodeType`；Fluent 已有 Switch/While **故意不进 JSON**。
3. 逻辑 ActionKey 使用**白名单**（Delay/Log/Assert/Calculate/SetVariable/Sync.* 等），**不等于**整个 `StandardActionsProvider`。
4. 书面同意：**不**把 SequenceExecutor 放进通用包。
5. 有带宽做 `StepConfig` 流程子集 vs 测试超集瘦身，且不破坏现有场景库。

未满足 → **禁止**开搬家 ADR / 新工程。

## 七、明确不做

| 不做 | 原因 |
|------|------|
| 新建 Workflow 工程并大搬家 | 无第二宿主；过早抽象；违反瑞士军刀定位 |
| SequenceExecutor / Builder 进「通用库」 | 电检产品核心（序列执行器），非横切件 |
| 整包 Engine 当工作流 NuGet | 硬绑工业栈；编译期带 SK |
| 无需求先拆 `StepConfig` 字段 | API 冻结与全库场景震动 |
| 把 Sync/信令、ExpectedSpec、Lease 标成无语境「工作流标准件」 | 假通用 |
| JSON 为「通用化」补 Switch/While | 与架构决策冲突 |
| 用 Temporal/Elsa/MES 替换或「升级」DynamicFlow | 领域不匹配 |
| 把 DynamicFlow 当 soft PLC / 周期扫描运行时 | 产品语义错位 |
