## 一、变量存在哪里：作用域与可见性

```
StepContext.Variables          ← 外层步骤上下文
  └── flowVariables (子作用域) ← DynamicFlow 启动时 CreateChildScope
        ├── 注入：step.Parameters 整包键值（含 WorkflowDefinition 等大对象）
        ├── 注入：WorkflowDefinition.Variables 初始工艺变量
        └── 每节点再 CreateChildScope（Args 映射进节点子作用域）
```

**要点**：

1. **读取**：`TryGet` 向上递归父作用域 → 后继节点能读到流程级变量。
2. **普通 `Set`**：只写**当前**作用域 → 节点结束后子作用域丢弃，后继**看不见**。
3. **`SetShared`**：写入**直接父级**（通常即 flowVariables）→ `SetVariable` / `Calculate` 走此路径，后继 Assert/WaitUntil **可见**。
4. **勿写绝对根**：`SetShared` 故意不穿透到外层 Step，避免污染外部步骤。

## 二、表达式求值：过滤裸标识符提升

实现：`ZL.Gear.Core.Workflow.WorkflowEvaluator`。

### 2.1 求值入口对照

| API | 用途 | 失败语义 |
|-----|------|----------|
| `EvaluateExpression` | **Calculate** 必用 | **抛异常** → Calculate → Failed（禁止退回公式字符串） |
| `EvaluateCondition` | WaitUntil / Assert L2 Condition / 节点条件 | 异常 → **false**（不抛；官方少依赖） |
| `EvaluateValue` | 以 `@` 开头的动态值 | 失败可退回原串（宽松；**Calculate 禁止走此路径**） |
| `Interpolate` | 日志 `${Name}` | 缺键：**保留原占位** `${Name}`；值为 null 则替换成文本 `"null"` |

### 2.2 何时变成「裸变量」

调用方仍把 `AsDictionary()` 全表交给求值器，但**只有同时满足**才提升为 DynamicExpresso 的 `Parameter`：

1. 键匹配 `^[A-Za-z_][A-Za-z0-9_]*$`
2. 键 ∉ 保留字表
3. 值（经 JValue 展开）为：`null` / `bool` / `string` / 可安全转 `double` 的数值
4. **排除**：`IDictionary`、非 string 的 `IEnumerable`、`Delegate`、`Task`、`TaskCompletionSource`、未知复杂对象

另外**始终**注入：

```text
Vars = 规范化后的整表字典   // 逃逸用；官方 Demo 不再示范
```

因此：即使 `Parameters` 里有巨大的 `WorkflowDefinition`，写法 `LimitOhm - MeasuredOhm` **仍然安全**——大对象不会变成标识符污染符号表。

### 2.3 新模式正确示例

```json
"Expression": "LimitOhm - MeasuredOhm"
```

```json
"Condition": "Ready"
```

```json
"Message": "裕量=${Margin}，泄漏=${LeakageMa}"
```

### 2.4 旧模式对照（仍能跑，但非官方）

```json
"Expression": "Convert.ToDouble(Vars[\"LimitOhm\"]) - Convert.ToDouble(Vars[\"MeasuredOhm\"])"
```

```json
"Condition": "Convert.ToBoolean(Vars[\"Ready\"])"
```

注意：

- 键名须用 **双引号** 字符串：`Vars["Ready"]`。
- `Vars['R']` 在 C# 表达式语义下易变成 **char**，属历史陷阱。
- `Vars["X"]` 类型是 `object`，直接 `Vars["X"] < 5` 不可靠——这正是旧官方被迫包一层 `Convert.ToDouble` 的原因。

## 三、判定（Assert）：L0 / L1 / L2

实现：`StandardActionsProvider` + `AssertCheckParser`。

### 3.1 三层分工

| 层 | Args | 角色 | 官方推荐度 |
|----|------|------|------------|
| **L0** | `Left` + `Op` + (`Right` **或** `RightVar`) + `Message` | 权威内核（工具生成/反糖化目标） | ★★★ 与 L1 等价语义 |
| **L1** | `Check` + `Message` | 一行比较糖，**反糖化为 L0** | ★★★ **手写首选** |
| **L2** | 仅 `Condition` | 自由表达式逃逸 | ★ 少用；复杂式再上 |

**互斥（双保险）**：

- `Check` 与 `Left`/`Op`/`Condition` **禁止同写** → Failed
- 结构化（Left+Op）与非空 `Condition` **禁止同写** → Failed
- `Right` 与 `RightVar` **须且仅一个**

### 3.2 L1 `Check` 文法（锁死）

```text
Ident  Cmp  ( Ident | Number | true|false | "string" )
Cmp ∈  >=  <=  ==  !=  >  <
```

| 允许 | 禁止 |
|------|------|
| `Margin > 0` | `A + B > 0`（算术） |
| `LeakageMa <= MaxLeakage` | `Math.Abs(X) > 5`（函数） |
| `CylStatus == "ARRIVED"` | `0 < A`（字面量须在**右侧**） |
| `A>=B`（无空格） | `A > 1e2`（科学计数） |
| | 中文标识、括号、超长（>256）、未知转义 |

字符串字面量仅支持 `\"` 与 `\\`。

### 3.3 L0 `Op` 枚举与别名

规范名：`Gt | Gte | Lt | Lte | Eq | Neq`
符号别名：`> >= < <= == !=`（以及实现支持的 `=` / `<>` 等，以 `TryNormalizeOp` 为准）

比较规则摘要：

- 数值：统一 `Convert.ToDouble`（InvariantCulture）
- `Eq`/`Neq`：bool 与 bool、string 与 string 可对齐比较
- 缺变量、无法转换、比较不成立 → **Failed**（禁止默认 true）

## 四、Type / ActionKey / Command 速查

### 4.1 `Type`（`WorkflowNodeType`）——枚举全集（仅 9 个）

| Type | 含义 | 必填相关字段 | ActionKey？ | Children？ |
|------|------|--------------|-------------|------------|
| **Action** | 普通原子动作 | `ActionKey` | **要** | 否 |
| **Measure** | 测量（带返回值） | `ActionKey`（测量键） | **要** | 否 |
| **Sequence** | 顺序容器 | `Children` | 否 | **要** |
| **Group** | 视觉/逻辑分组 | `Children` | 否 | **要** |
| **Parallel** | 并行动作容器 | `Children` | 否 | **要** |
| **ParallelMeasure** | 并行测量容器 | `Children` 全为 Measure | 否 | **要** |
| **Delay** | 延时 | `DelayMs`（默认 1000） | 否 | 否 |
| **Retry** | 重试包装 | `ActionKey` + RetryCount/IntervalMs | **要** | 通常无 Children |
| **WaitUntil** | 条件轮询 | `ActionKey` **或** `Condition` + TimeoutMs/IntervalMs | 二选一 | 否 |

### 4.2 明确不存在的 Type（勿写进官方 JSON）

| 名字 | 说明 |
|------|------|
| `Switch` / `While` / `If` | **仅 Fluent**（`MicroWorkflow`）；JSON 枚举无此值 |
| `Threshold` | 属于 **Sampling.Trigger.Type**，不是节点 Type |
| `Cleanup` | **不是** Type，也不是内置 ActionKey |

### 4.3 内置 `ActionKey`（动作 Registry · 官方可写）

#### 纯 Action（`RegisterAction`）

| ActionKey | 用途 | 主要 Args | 典型 Type |
|-----------|------|-----------|-----------|
| **Delay** | 延时 | `DelayMs`/`Duration`/`Delay`；或步骤 TimeoutMs | 也可用节点 `Type:Delay`（无 ActionKey） |
| **System.Delay** | 同上 | 同上 | Action |
| **Log** | 打日志 | `Message`（支持 `${}`） | Action |
| **Log.Info** | 打 Info（用 Description） | — | Action |
| **SetVariable** | 写流程级变量 | `Key`,`Value`（**SetShared**） | Action |
| **Calculate** | 表达式求值写变量 | `Expression`,`OutputKey` | Action |
| **Assert** | 判定 L0/L1/L2 | `Check` 或 Left/Op/Right\|RightVar 或 Condition；`Message` | Action |
| **Write** | 设备写 | 需 `Target`；`Command` 默认 Write | Action |
| **Read** | 设备读（作 Action 时可能丢 Measurement 语义） | 需 `Target`；`Command` 默认 Read | Action **或** Measure |
| **Query** | 设备查询 | 需 `Target`；`Command` 默认 Query | Action **或** Measure |
| **Sync.SignalStart** | 并行主从：通知开始 | 依赖信令对 | Action |
| **Sync.StopMaster** | 并行主从：停止 | 依赖信令对 | Action |

#### 纯 Measurement（`RegisterMeasurement`）

| ActionKey | 用途 | 主要 Args | 必须挂的 Type |
|-----------|------|-----------|---------------|
| **GenericMeasure** | 通用采样测量 | `Sampling`（SampleCount/Mode/Calculator…）；`Command`；需 Target | **Measure** / ParallelMeasure 子节点 |
| **Read** | 同上双注册 | 见上 | **推荐 Type=Measure** |
| **Query** | 同上双注册 | 见上 | **推荐 Type=Measure** |

#### 双注册规则（极重要）

`Read` / `Query` 同时存在于 Action 与 Measurement 表：

| 挂法 | 结果 |
|------|------|
| `Type: Measure` + `ActionKey: Read` | 走测量路径，可进 ParallelMeasure / 测量集合 |
| `Type: Action` + `ActionKey: Read` | 走动作路径，**可能丢 Measurement** |
| `Type: Parallel` 直挂可 ResolveMeasurement 的键 | **构建期 Failed**（须改 ParallelMeasure） |
