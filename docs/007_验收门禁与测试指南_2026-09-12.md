## 二、新行业 Handler 额外检查

- [ ] 限值/配方：`StepArgSource.ArgsOnly` + `TryRequire*`（**禁止** `All` / `context.Get` 读必填限值）
- [ ] 写流程：`args.SetShared`（**禁止** Handler 内 `Variables.Set`）
- [ ] 读前序：`GetFlowString` / `VariablesOnly`（**禁止**用 `All` 误读 Global）
- [ ] 可选 Args 覆盖：键存在则 fail-closed，**禁止** `TryGet` 失败后静默回退（见 ProbeChannel 修正）
- [ ] 判据在 JSON `Assert` / `ExpectedResults`，不在 Handler 内 if 限值
- [ ] `Assert` L1 `Check` **单条件**：禁止 `&&` / `||` / 括号；多条件拆成多条 Assert（否则 `AssertCheckParser` 报「含多余字符」→ 步骤 Failed）
- [ ] `ParameterSchema` 字符串与 TryRequire 字段**人工对齐**（无自动绑定）
- [ ] IndustryKit verify 或等价场景含 **故意 FAIL + 超时**（防假绿）

## 四、Agent / CI 验证最佳实践

### 4.1 产线 Handler 最佳实践（已验证）

| 实践 | 做法 | 反例（灾难） | 锚点 |
|------|------|--------------|------|
| 限值 fail-closed | `ArgsOnly` + `TryRequire*` | `context.Get` / `All` 静默兜底 | `ApplyRecipeHandler.cs` |
| 写流程变量 | `args.SetShared` | `Variables.Set`（节点级，后继读不到） | `ContextVariableStore.cs` |
| 读前序状态 | `GetFlowString` / `VariablesOnly` | `All` 误读 Global | `MarkCompleteHandler.cs` |
| Schema 双轨 | `ParameterSchema` = 文档；运行时手写 TryRequire | 以为注解自动校验 | docs/121 §十二 **不做**自动解析 |
| 可选 Args 覆盖 | **键存在** → 必须解析成功；**键不存在** → 再读 Variables | `TryGet(..., out _)` 链式回退吞错 | `ProbeChannelHandler.cs` |
| 规格判定 | JSON `Assert` / `ExpectedResults` | Handler 内 if 限值（除安全硬中断） | IndustryKit 四场景 verify |
| 门禁非假绿 | verify 含 **故意 FAIL + 超时** | 只跑 HappyPath | `VerificationCatalog.cs` |

### 4.2 配方 JSON 踩坑

| 踩坑 | 现象 | 正确做法 |
|------|------|----------|
| Assert `Check` 写 `&&` | `AssertCheckParser` 报「Check 含多余字符」→ 步骤 **FAIL** | L1 `Check` **单条件**；多条件拆多条 Assert |
| `WorkflowDefinition.Variables` 预置 LimitOhm + Handler 用 `All` | 省略 Args 仍读到旧限值 → **换配方不换限** | 限值只来自本步 Args |
| 从 `docs/archive/` 抄场景 | 含 `Quantity`/`WaitCondition`/`Toggle` 等废弃或未实现方言 | **权威库**：`demos/IndustryKit/Scenarios/` |
| Continuous + Threshold 期望「命中即停」 | 实测 `Demo_Sampling_Continuous`：日志 **1 次**设备读、耗时 ~**5s**（≈ `TotalTimeoutMs`） | 文档诚实：本橱窗演示 **Continuous + 超时兜底**；Stop 未提前结束属 Sensing 边界，非 JSON 写错 |
| Sampling 字段名 | `Quantity`/`IntervalMs` 旧字段 | `SampleCount` / `SampleIntervalMs`（`SamplingConfigModel`） |

### 4.3 Agent 跑 `dotnet` 时的踩坑

| 踩坑 | 现象 | 原因 | 最佳实践 |
|------|------|------|----------|
| 沙箱无 NuGet | ~30s 后 `Unable to load the service index for source` | Agent 默认网络白名单不含 NuGet | `dotnet restore/build` 需 **full_network**；或在本机/CI 跑 |
| MSBuild 假挂 | **~10 分钟**后 `Build FAILED`，**0 Error(s)** | MSBuild  out-of-proc 节点超时/僵死 | 重试前 `killall MSBuild dotnet`；单项目 build 缩小范围 |
| `\| tail` 误判成功 | Agent 报 exit 0，实际 dotnet 已失败 | 管道 exit code 来自 **tail** 而非 dotnet | 判断成败看 **dotnet 退出码** 或日志关键字（`PASS`/`FAILED`），勿只看 tail |
| 每次 `dotnet run` 隐式编译 | 单次验证 **5～10 分钟** | 重复 restore/build | 先 `dotnet build`，再 `--no-build` 跑场景 |
| IndustryKit verify 假绿 | 脚本设 `ZL_GEAR_LICENSE_TEST_MODE` 绕过门禁 | 公开轨 **G0-4 禁止**任何授权 bypass | 仅跑 `bash check_release_public.sh`；`verify.sh` **不得** export `ZL_*LICENSE*` |

## 五、方向性审查（按错方案实施 = 产线灾难）

### 5.1 🔴 禁止方向（实施即灾难）

| # | 错误方案 | 灾难后果 | 正确方向 |
|---|----------|----------|----------|
| D-01 | ParameterSchema 自动解析/JSON Schema 绑定 | 以为注解即校验，漏写 TryRequire → **漏检放行** | Schema=文档；运行时 **StepArgsReader 手写** |
| D-02 | 产线限值用 `context.Get` / `StepArgSource.All` | Variables/Global **静默兜底**错误限值 → **误 PASS** | 限值/RecipeId：**ArgsOnly + TryRequire*** |
| D-03 | 行业 Handler 用 `Variables.Set` | 写节点级，后继 Assert/Calculate **读不到** → 假执行/假合格 | **`args.SetShared`** |
| D-04 | `WorkflowDefinition.Variables` 预置 LimitOhm 等限值，Handler 用 All 读取 | Args 省略仍从 Variables 拿到旧限值 → **换配方不换限** | 限值只来自 **本步 Args** |
| D-05 | 可选 Args「TryGet 失败静默回退」链（`out _` 丢错误） | Args 含非法 MeasuredOhm 时回退 SimulatedOhm → **掩盖坏数据** | 键存在→必须成功；键不存在→再读 Variables |
| D-06 | 为 OpenTAP/TestStand 对齐做 MES/设计器/Workflow NuGet/ALC | 偏离瑞士军刀，维护成本爆炸，无消费者 | 换 JSON + 扩展包；多站多进程 |
| D-07 | 仅跑 HappyPath verify | Assert/超时回归缺失 → **假绿发版** | 四用例语义不可删 |

### 5.2 🟡 已知限制（不是方向错误，但须知情）

| # | 限制 | 影响 | 缓解 |
|---|------|------|------|
| L-01 | `WorkflowGlobal` 单例 | 同进程第二套 DI 不生效 | 一站一进程；测试 `Reset()` |
| L-02 | 插件目录 `LoadFrom` 无 CI | 外置 DLL 上线风险 | 有工单再做集成测试 |
| L-03 | Parallel 同键 `SetShared` | 末写覆盖 | 分支用不同键或 Sequence |
| L-04 | JSON 无 Switch/While | 复杂分支须 Fluent/测试树 | docs/130 有意取舍 |

### 5.3 🟢 已验证方向（可放心按此实施）

| 方向 | 验证证据 |
|------|----------|
| IndustryKit = 新行业模板（非 Seat） | `check_release_public.sh` 第 3 步；4 场景 verify |
| StepArgsReader 来源策略 | 28 单测 + docs/140 |
| 执行≠评估（Assert 在 JSON） | `Station_AssertFail.json` 故意 FAIL |
| 扩展双面注册 | `PluginChainLoadTests` |
| **不做** Schema 自动绑定 | docs/121 + 121/130/141 三处一致 |
